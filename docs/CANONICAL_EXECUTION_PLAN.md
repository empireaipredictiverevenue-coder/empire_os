# EmpireOS Canonical Execution Plan

Status: **CURRENT EXECUTION ORDER**  
Architecture reference: `docs/BLUEPRINT_V6.md`

This document controls execution sequencing from 2026-09-23 onward. Blueprint
v6 remains the architecture and historical roadmap reference, but parallel work
recorded there does not override this execution order.

## Permanent closeout sequence

Every phase follows the same mandatory sequence:

**Build → Integrate → Test → Verify → Founder Console → Upgrade & Enhance → Revenue Expansion → Re-test → Close Phase**

A phase is not closed merely because code exists.

New ideas are captured against the correct phase. They do not interrupt the
current phase unless they reveal a genuine blocker, security issue,
revenue-critical dependency or fundamental correctness problem.

## Phase 4 — Commercial Exchange

Build the Supabase-native commercial exchange around:
- lanes;
- corridors;
- buyer seats;
- capacity;
- territory/exclusivity;
- qualified inventory;
- overflow inventory;
- governed allocation.

Buyer capacity gates delivery, never acquisition. When seats are full, Empire
continues acquiring qualified opportunities and retains overflow inventory for
later allocation, alternative corridors, marketplace/feed routes or nurture.

Revenue expansion includes buyer-seat subscriptions, corridor subscriptions,
dynamic buyer pricing, capacity/usage economics, overflow monetisation,
margin-aware routing, demand pre-selling, reserved future capacity and
territory/exclusivity premiums.

## Revenue feature rule

A feature should materially support at least one of:
- revenue;
- conversion;
- margin/cost reduction;
- retention;
- defensibility;
- data quality;
- operational control.

Large ideas that do not belong in the active phase are recorded for their
assigned phase rather than interrupting delivery.

## Truth rules

- No synthetic production data.
- Unknown remains unknown.
- Forecast/model score/send/payment request is not revenue.
- Payment evidence is not automatically recognized revenue.
- Recognized revenue is not automatically realized gross profit.
- Historical pricing is not current approved pricing.
- Registry state is not production proof.
- Runtime artifact presence is not revenue proof.
- Protected recovery/toop trees remain untouched.
- Autonomous execution remains OBSERVE unless separately and explicitly
  governed through an approved authority boundary.
