# EmpireOS SEO/AEO/GEO/A2A — Four-Surface Discovery Observer

**16 October 2026 · Status: source-only candidate, not deployed · OBSERVE**

## Why this exists
Use a single, bounded read-only preflight to validate the *public discovery
contract* linking human organic traffic, AI answer extractability,
generative-engine source credibility and agent-to-agent discovery. This is not
a new SEO agent, server, scheduler, database, collector, tracking pixel or
external AI model. The existing daily AI SEO Research Council and ASTRA
remain the owning operating cadence.

## Placement and ownership
- Source: `empire_os/search_intelligence/four_surface_discovery.py`
- Entry point: `scripts/review_four_surface_discovery_readonly.py --review-only`
- SEO and AEO owners: existing SEO Director + flagship website ASTRA owner.
- GEO owner: Search Intelligence/SEO evidence owners. This review cannot prove
  independent AI citations, answer mentions or generated-search traffic.
- A2A owner: existing `agent_web.py`, `a2a_runtime.py`,
  `public_gateway.py` teams. Do not duplicate A2A endpoints.
- Conversion truth: EmpireDB and the authenticated founder CRM, separately.

## Authority and data
- Seven exact first-party HTTPS GET URLs; no POST, headers containing tokens,
  broader crawls, email, records with customer identities or provider writes.
- Network responses limited to 350kB; returned summary has no raw HTML,
  individual enquiries, Google queries, model prompts or sensitive payloads.
- SEO report checks three existing public pages, sitemap count, canonical,
  title/H1, noindex, link path. It does not measure crawl ranking.
- AEO report flags heading coverage and editorial-linking gap; it does not
  claim ChatGPT/Google AI Overview citations.
- GEO report **explicitly UNKNOWN** for actual external AI mentions.
- A2A report cross-checks nine skill declarations and capability names,
  published HTTPS protocol bindings and safe discovery flags; does not send
  messages or assert that authentication, task execution or sale occurred.
- EmpireDB PostgreSQL is canonical. No Supabase production route.

## Integration without collision
The owning ASTRA/SEO operator may call the one-shot read-only CLI from the
existing governed research job, **after** source review and merge approval.
Never introduce a timer/daemon or edit current shared ASTRA dispatcher. If a
network or first-party provider is unavailable, status remains UNKNOWN/failed.
The previously prepared DFW AEO contextual link is a separate, isolated
candidate; deployment needs the current site owner and existing static
release process. Do not alter protected `/roofing` indexation or host routing.
