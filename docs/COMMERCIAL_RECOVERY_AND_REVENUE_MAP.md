# Empire Commercial Recovery & Revenue Map

Date: 2026-09-21
Status: CANONICAL RECOVERY / COMMERCIALIZATION INDEX

## Purpose

This document prevents Empire AI / EmpireOS from collapsing into a single-product,
single-channel or MRR-only business while the production roadmap advances.

It reconciles:
- current production truth in `BLUEPRINT_V6.md`;
- the company/product model in `MASTER_BUSINESS_BLUEPRINT.md`;
- historical commercial assets recovered through
  `LEGACY_COMMERCIAL_INTELLIGENCE_RECOVERY_INDEX.md`;
- the salvage rules in `ASSET_HOLDING_AND_SALVAGE_POLICY.md`;
- the Marketing Department and GTM blueprints.

Historical assets are memory and evidence of prior intent, not automatic production
authority. Current runtime + canonical Supabase remain the final evidence.

## Commercial doctrine

Empire is a multi-revenue Predictive Revenue company.

MRR is one scale engine, not the whole business model.

Canonical revenue lanes:
1. immediate / transactional revenue;
2. recurring subscription / seat / territory / intelligence revenue;
3. usage / API / data revenue;
4. performance / value-metered revenue where terms and evidence support it;
5. managed execution / high-touch service revenue;
6. enterprise / private-capital / portfolio revenue;
7. white-label / reseller / partner revenue;
8. marketplace / infrastructure economics where governance supports it.

Commercial progression:

FIRST CASH
-> RECURRING REVENUE
-> DATA / API
-> PERFORMANCE / VALUE METERING
-> MANAGED EXECUTION
-> ENTERPRISE
-> WHITE LABEL / CHANNEL
-> MARKETPLACE / INFRASTRUCTURE

No stage replaces the others. Astra should eventually allocate effort across the
portfolio using verified demand, cost, margin, capacity, outcome and risk evidence.

## Recovery rule

Every recovered product or GTM asset must be classified before promotion:

- PRODUCTION
- ACTIVE_BUILD
- INCUBATE
- SALVAGE_CANDIDATE
- REBUILD_LATER
- REFERENCE_ONLY
- RETIRED
- FOUNDER_GATE

Recovery never means blindly restoring old code.

Legacy SQLite, synthetic evidence, stale contacts, Solana/USDC settlement,
Vapi/Twilio regressions, unverified claims and obsolete direct-execution paths stay
retired unless independently rebuilt against the current architecture.

## Commercial catalog rule

The canonical commercial-product catalog remains fail-closed.

A recovered product may appear in this recovery map before it is inserted into the
production commercial catalog.

Promotion to a sellable catalog item requires:
1. clear product identity and buyer;
2. deliverable / fulfilment contract;
3. current pricing decision or evidence;
4. acquisition and fulfilment cost basis;
5. minimum-margin policy;
6. evidence / provenance;
7. effective window;
8. tests and read surface;
9. governed commercial authority.

Historical pricing is never silently promoted as current pricing.
